# GRIT WMS: HTTP-адаптеры WB / Ozon / Яндекс Маркета

## Что готово

- Реальные HTTP-клиенты с **фиксированными HTTPS-адресами** и методами чтения заказов.
- Заголовки авторизации по площадкам: WB `Authorization`, Ozon `Client-Id` + `Api-Key`, Яндекс `Api-Key`.
- Ограничение частоты **на процесс** (консервативный интервал) и максимум 3 попытки для чтения.
- HTTP 429/420, 500/502/503/504 и временные сетевые сбои: ограниченный backoff до 8 секунд.
- Редиректы не выполняются, таймауты фиксированы, превышение размера тела ответа отклоняется.
- Нормализация ответа на базе существующего `marketplace_lab.py`.
- Отдельная таблица `grit_marketplace_sync_log`: **только метаданные**, без токенов, покупателей, содержимого заказов.
- Руководитель: `/manager/integrations/http`. Кнопки обращаются **только к MockTransport**, никогда к реальным площадкам.
- Защита POST-тестов: manager-сессия и CSRF-токен из страницы.

## Важно: что НЕ готово

- Нет многоарендного OAuth / WB service integration onboarding, хранилища секретов нескольких продавцов, общей распределённой очереди и синхронизации всех страниц.
- Нет подтверждения корректности реальных ответов всех площадок. Без законного доступа продавца это остаётся неподтверждённым.
- Нет переноса заказов в основную WMS, автоматического подтверждения сборки или передачи статусов: существующие рабочие процессы не меняются.
- Лимитер **локален процессу**. При нескольких процессах необходима общая квота (Redis/БД), плюс управление бюджетом лимитов по продавцу, методу и площадке.
- Реальное чтение — только **по отдельному явному вызову** функции `authorized_read_once` в серверном коде. Веб-эндпоинта для этого нет; включение флага ничего само не запускает.
- Журнал использует уже настроенную БД GRIT, но создаёт **отдельную таблицу** при обращении к тестовому экрану. Тестовые заказы в складских таблицах не сохраняются.

## Будущая авторизация одного продавца в отдельной среде

Никогда не передавайте ключи в GitHub, URL, чат, браузерные формы или логи. Используйте только защищённые переменные окружения сервера после письменного разрешения владельца кабинета и выдачи минимально необходимого доступа.

| Площадка | Серверные переменные |
|---|---|
| Wildberries | `GRIT_MP_WB_TOKEN` |
| Ozon | `GRIT_MP_OZON_CLIENT_ID` и `GRIT_MP_OZON_API_KEY` |
| Яндекс Маркет | `GRIT_MP_YANDEX_API_KEY` и `GRIT_MP_YANDEX_BUSINESS_ID` |

Для отдельного, заранее разрешённого чтения также нужен `GRIT_MARKETPLACE_LIVE_READ_ENABLED=1`. По умолчанию он **выключен**. Текущий вариант env-переменных подходит только **для одного разрешённого селлера на инстанс** и НЕ является подходящей схемой коммерческого SaaS.

Запросы выполняются только на:
- `GET https://marketplace-api.wildberries.ru/api/v3/orders/new`
- `POST https://api-seller.ozon.ru/v4/posting/fbs/list`
- `POST https://api.partner.market.yandex.ru/v1/businesses/{businessId}/orders`

Ozon использует актуальную v4-версию метода (старую v3 объявили к отключению в 2026 году).

## Тестирование

```bash
python -m pip install requests
python -m unittest -v test_marketplace_http
```

Это офлайн-тесты. Они не обращаются к Wildberries, Ozon, Яндекс Маркету и не требуют API-ключей. В одном тесте поднимается временная SQLite-БД только для проверки журнала.
