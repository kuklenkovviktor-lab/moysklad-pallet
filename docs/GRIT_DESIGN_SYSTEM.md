# GRIT WMS: единый дизайн интерфейсов

**Обязательное правило:** каждый новый модуль, экран и переход оформляются сразу в тёмном стиле GRIT. Нельзя добавлять белые формы или светлые карточки «временно».

Для панели руководителя используется единая таблица стилей `grit_theme.py` (публикуется как `/grit-ui.css`). Отдельные терминалы, публичный вход и партнёрский портал используют ту же палитру в локальных стилях, без изменения складской логики.

На всех страницах, включая загрузку и ошибки, фон `#09121e`. Проверять обе ориентации телефона и мобильный Safari.

**Обязательный стандарт печати посещаемости:** QR «ВХОД» и «ВЫХОД» печатаются строго на отдельных термоэтикетках **58×40 мм**, по одной этикетке на страницу. Печатный CSS обязан задавать `@page { size: 58mm 40mm; margin: 0; }` и предотвращать разбиение каждой этикетки на несколько страниц. Не применять A4, масштабирование содержимого или длинный лист. Проверять предпросмотр в браузере: **ровно 2 страницы**, без пустых листов.

**Исключения:** белый фон QR/штрихкода, лист печати A4 и этикетка 58×40 мм. Исключения должны быть ограничены самим кодом или режимом `@media print`; окружающий экран остаётся тёмным.


## Навигация: полупрозрачные pill-капсулы

Все верхние ссылки возврата и навигационные переходы оформляются одинаково, без голых текстовых ссылок.

- Класс: `.grit-nav-pill` (общие стили в `grit_theme.py`, отдельные экраны повторяют параметры).
- Форма: `border-radius:9999px`, минимальная высота `44px`.
- Фон: `rgba(126,164,199,.12)`; hover: `rgba(126,164,199,.22)`.
- Обводка: `1px solid rgba(170,204,237,.22)`.
- Текст: `#f1f6ff`; стеклянный эффект: `backdrop-filter:blur(12px)`.
- Клавиатурный фокус: `#ff9230`. При `prefers-reduced-motion` переходы отключаются.
- Никаких изменений в рабочих кнопках сборки, сканерах, формах, QR и печати. На печати навигацию скрывать.

Ссылки в существующих верхних панелях (`.top a[href]`) получают этот стиль централизованно, но функциональные `.button` и `.action` исключены. Для новых страниц использовать явный класс `.grit-nav-pill`.

## Процесс посещаемости (обязательный минимальный сценарий)

**QR «ВХОД» → личный бейдж → автоматическая запись прихода.**
**QR «ВЫХОД» → автоматическая запись ухода, закрытие производственной смены и завершение авторизации.**

После успешной отметки **не отображать страницы с результатом**: вход перенаправляет на `/fbs`, выход (после закрытия серверной сессии) на `/login?attendance_exit=1`. Страница входа очищает локальные данные прежнего сотрудника и убирает служебный параметр из URL. Повторная отметка ВХОД идемпотентна (не создаёт вторую запись) и тоже ведёт на главную WMS. При ошибках записи или закрытия смены переход не выполняется; показывается причина, серверная сессия сохраняется.


QR старшего для завершения смены **отключён**: никаких дополнительных сканов и кнопок подтверждения в обычном процессе. Ссылки старой страницы `/exit` перенаправляются на `/attendance/out`; старые API выхода/генерации QR возвращают HTTP 410. Приход и уход создаются через CSRF-защищённый POST, а не GET. Запись ухода и закрытие смены выполняются в одной транзакции; если операция не удалась, посещение не должно частично закрыться.

Физический формат обоих QR: строго **58×40 мм**. Руководитель может исправлять зависшие смены через существующие административные инструменты; это не часть обычного маршрута сотрудника.

## Перед выпуском

1. Проверить фон, карточки, таблицы, формы, окна, состояния ошибок и пустые экраны.
2. Проверить белый QR, читаемость штрихкодов, индивидуальную и массовую печать.
3. Прогнать статические UI-тесты и синтетические сценарии, не трогая рабочую базу.
4. После объединения PR подтвердить статус автодеплоя HOSTKEY и проверить UI визуально.

Любые новые PR с интерфейсными изменениями обязаны сохранять этот контракт. Это часть определения «готово», а не отдельная косметическая задача.
