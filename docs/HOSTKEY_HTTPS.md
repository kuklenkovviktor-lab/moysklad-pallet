# HTTPS для gritwms.space — подготовленная конфигурация, без деплоя

`compose.https.yaml` — необязательный overlay к основному compose.yaml. Не включать
до отдельного разрешения на DNS/HTTPS/cutover. Это Caddy вместо самостоятельного
nginx/certbot: не запускайте оба reverse proxy на портах 80/443.

## Поведение

- Автоматический HTTP → HTTPS redirect и получение/обновление сертификатов ACME.
- `/data` и `/config` сохраняются на постоянном диске в GRIT_DATA_ROOT/caddy;
  удаление контейнера не должно удалять сертификаты/ACME account. Не очищать их
  при обновлении. Продление выполняет Caddy, внешний cron/certbot не нужен.
- TLS defaults Caddy; HSTS без includeSubDomains/preload, nosniff, DENY framing,
  frame-ancestors, Referrer-Policy. Строгий default-src CSP не включён: существующий
  мобильный UI использует inline JS и внешние библиотеки.
- camera=(self) сохраняет работу сканирования камерой на HTTPS; Secure/HttpOnly
  session cookie остаются в ведении приложения.
- Служебные health/startup/system-status/metrics/debug/setup закрыты снаружи.
  Docker healthcheck app обращается напрямую к контейнеру и не блокируется.
- Менеджерские/API-admin/print-agent маршруты допускаются только с
  GRIT_ADMIN_CIDRS; по умолчанию разрешены только loopback CIDRs, то есть внешний
  менеджерский вход закрыт. Авторизация приложения и bearer token агента при
  разрешённом IP всё равно обязательны. Не используйте 0.0.0.0/0 для обхода.
- Бейдж сотрудника, /login, /fbs, партнёрский портал и публичные assets остаются
  доступны согласно серверной авторизации. Этот PR не исправляет слабые форматы
  бейджей: допуск в Интернет требует отдельного решения об этом риске.
- Переданный клиентом X-Forwarded-For заменяется адресом TCP-подключения к Caddy;
  приложение не получает произвольный левый IP для обхода rate limiter.
  Если позже появится CDN/другой proxy, trusted proxies настраивать отдельно.
- Overlay убирает ВСЕ host-port mappings app. Caddy соединяется с app:8000 по
  web-сети. PostgreSQL порт не публикуется и в overlay не меняется.

## Проверки без настоящего DNS/сертификатов

```
docker pull caddy:2-alpine
docker build -t grit-wms:hostkey .
python3 deploy/verify_https.py
```

Runner создаёт внутреннюю Docker-сеть, фиктивный upstream и Caddy с `tls internal`
на тестовом hostname. Внешний ACME не вызывается. Клиент проверяет сертификат
через одноразовый тестовый CA, без verify=False. Проверяются TLS, redirect,
заголовки, Secure cookie, разрешение камеры, отказ служебных/админских маршрутов
и замена поддельного XFF. Контейнеры теста удаляются; никакие существующие данные
не удаляются. Это не проверка выдачи/продления публичного сертификата и не
физический тест камеры телефона.

Синтаксис production Caddyfile проверяется без запуска сервера:

```
docker run --rm --network none -e GRIT_ACME_EMAIL=test@example.invalid \
  -v "$PWD/deploy/https/Caddyfile:/etc/caddy/Caddyfile:ro" \
  caddy:2-alpine caddy validate --config /etc/caddy/Caddyfile
```

## Предварительные условия для будущего включения (вручную, после review)

1. Проверить отсутствие конфликтов портов и согласовать выбор Caddy. Проверить
   подготовленный cutover/rollback PostgreSQL, не включать два writers.
2. Задать корректные A/AAAA и достижимость VPS только после разрешения владельца.
   Если IPv6 не настроен, нельзя оставлять неработающую AAAA. Сейчас DNS не менялся.
3. Разрешить входящие 80/tcp и 443/tcp; 443/udp необязателен для HTTP/3. Наружу
   нужны DNS и HTTPS до ACME/CA. Не открывать 5432.
4. В существующую локальную .env добавить GRIT_ACME_EMAIL и GRIT_ADMIN_CIDRS
   (адрес склада/администратора или доверенной VPN, CIDRs через пробел).
   Ничего не публиковать в Git; не печатать полный compose config.
5. Подготовить только новые каталоги caddy/data и caddy/config с владельцем,
   соответствующим UID контейнера (официальный образ здесь запускается root).
   Не менять владельца/права существующей PostgreSQL и backup-каталогов.
6. Проверить имеющиеся images/digests, конфигурацию и сохранить предыдущий
   согласованный вариант. Compose требуется >=2.24.4 из-за !override; HOSTKEY
   Compose v5.6.1 поддерживает этот синтаксис.

Шаблон команд для отдельного разрешённого этапа, НЕ выполнялся при разработке:

```
docker compose -f compose.yaml -f compose.https.yaml config --quiet
# После разрешения на публичный запуск:
docker compose -f compose.yaml -f compose.https.yaml up -d
```

Команда up может пересоздать app для снятия loopback-порта: это не безостановочное
обновление и не команда для автоматического выполнения ночью. Проверить вход
со склада и мобильного телефона, cookies/camera, менеджерский allowlist, отсутствие
5432 и успешное ACME issuance. Служебные /api/health снаружи должны давать 404;
оператор смотрит Docker health или /login по HTTPS.

## Продление и наблюдение

Caddy заранее обновляет сертификаты, пока работают DNS/порты/исходящая сеть и
доступен постоянный /data. Нужны внешняя проверка срока сертификата и уведомления
о сбоях; остановленный VPS не может сам оповестить. Следить за системными логами
Caddy (Docker local rotation 5×10MB). ACME account/cert storage — чувствительные
данные, не отправлять их в GitHub/чат. Тесты не доказывают продление на HOSTKEY:
его проверка остаётся приёмкой после разрешённого развёртывания.

Откат proxy требует отдельного согласованного переключения маршрута/порта;
не включать второй proxy и не удалять сертификаты/базы для «починки».
