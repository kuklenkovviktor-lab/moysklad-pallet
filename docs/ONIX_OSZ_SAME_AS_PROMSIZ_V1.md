# ONIX WMS 1.0: ОСЗ работает ровно как Промсиз

## Единственный новый процесс для ОСЗ

1. Руководитель создаёт отдельного партнёра «ОСЗ» в `/manager/partners` с отдельными учётными данными.
2. Представитель ОСЗ открывает `/partners/login`, загружает Excel по **тому же шаблону**, что и Промсиз:
   - `Артикул | Палет | Ед. в палете | Количество, ед.`; либо
   - `Палета | Артикул | Количество`.
3. ONIX создаёт **уникальный `ONIX-PAL-...` QR для каждой физической палеты**. Состав, количество и поставщик хранятся в базе; сам QR содержит только идентификатор.
4. Поставщик печатает этикетки А4 (массово по загрузке/поставке) и наклеивает их на палеты.
5. Приёмщик на складе открывает стандартную приёмку в ONIX, выбирает черновик МойСклада, сканирует `ONIX-PAL`, проверяет артикул и количество, подтверждает.
6. ONIX записывает позицию в МойСклад, журнал подтверждения и статус палеты. Второй скан той же палеты запрещён, даже при новом ID запроса.
7. В истории партнёра доступны статус и редактирование состава **до** начала приёмки.

## Что не требуется

- Никаких дополнительных кодов, наклеек, полей или сверок с внутренней системой маркировки ОСЗ.
- Не создаём отдельный модуль или специальный режим сканирования для ОСЗ.
- Промсиз и ОСЗ работают через **одинаковый** модуль, но под разными логинами и каждый видит только свои записи.
- Старый специализированный API приёмки ОСЗ остаётся в коде для совместимости с историческими операциями и **не используется в новом процессе**. Его экран на складе скрыт, новые палеты принимаем только по QR ONIX.
- Существующие записи и исторические таблицы в рабочей базе не удаляем.

## Проверка перед закрытием задачи #45

- [ ] Войти в отдельный кабинет ОСЗ; чужие поставки недоступны.
- [ ] Загрузить Excel: 2 полные палеты + 1 неполную, проверить количества и три уникальных QR.
- [ ] Напечатать А4 и проверить читаемость QR камерой и сканером.
- [ ] Принять **одну** новую палету в отдельный тестовый документ МойСклада.
- [ ] Повторить скан: товар в МойСкладе не должен увеличиться повторно.
- [ ] Проверить приёмку при нестабильной сети без автоматической повторной записи.
- [ ] Сверить фактический Excel ОСЗ с поддерживаемыми заголовками, при необходимости адаптировать формат (только импорт, не второй модуль).

**Запуск ONIX 1.0:** до 10.11.2026. Эти тесты не меняют правила текущей FBS-сборки.
