## HOSTKEY — один сценарий

Уже выполнен. Каталог проверенной копии `/opt/grit-data/testing/usb-bridge-pr208-f4def01` назван по первой ревизии; текущий SHA смотреть через git. Повтор безопасно возвращает ту же попытку:

```bash
python3 /opt/grit-data/testing/usb-bridge-pr208-f4def01/deploy/prepare_usb_physical_test.py --printer-id demo-a96105f97bec --approve-one
```

ID взят из существующего активного принтера изолированной БД, линия Б. Название для поиска не используется, дубликаты принтеров не создаются. На другом стенде указать его точный ID.

При первом обновлении старой версии добавить `--refresh-demo`: изменяется только проверенный demo-app на localhost:18769 и ротируются тестовые секреты. Этот флаг уже использован, обычным повторам он не нужен. Проверяются фиксированный `/tmp/grit-pr208-demo.state`, права файла, отдельная сеть только demo-app/PG17, порт, synthetic DSN/namespace и версия 17. При несоответствии — FAILED без production fallback.

`--approve-one` — явное полномочие администратора тестового стенда действовать как `demo-manager` для одной синтетической попытки. Скрипт проходит настоящий `/demo/login` с закрытым паролем, получает manager session и CSRF; endpoint повторно проверяет manager/CSRF. Это не производственное согласование каждой этикетки.

Секреты проверенного demo-контейнера читаются в память, не печатаются и не передаются в argv. Новый app получает временный файл env с правами 0600, удаляемый после запуска. При неуспешном старте возвращается старый demo-app. Метаданные отката: `/root/.config/grit-usb-bridge/rollback.json`. Старые контейнеры и БД не удаляются.

## Windows — один сценарий

PowerShell из корня этой ветки; нужны Python/pywin32 и настроенный `ssh grit`:

```powershell
.\deploy\Run-GritUsbTest.ps1 -Mode Check
```

Первый Check автоматически выполняет Enroll по SSH и сохраняет DPAPI. SSH может спросить парольную фразу ключа — не токен агента. Отдельное окно туннеля не требуется. После ротации стенда/токена использовать `-Mode Enroll`, затем Check.

На этом компьютере Enroll и Check **уже выполнены**. После установки рулона 58×40 мм оператор может явно выполнить единственную физическую попытку:

```powershell
.\deploy\Run-GritUsbTest.ps1 -Mode Print
```

**Codex эту команду не выполнял.** Отправляется одна локальная TSPL-этикетка SYNTHETIC / NOT WB. Другие принтеры, системный принтер по умолчанию и не-USB порты запрещены. Оригинальных WB-стикеров и реальных заказов нет.

## Статусы и защита

- READY: стенд, принтер и одно привязанное разрешение проверены; печати нет.
- SUBMITTED_TO_WINDOWS: spooler принял задание; **это не доказательство выхода бумаги**.
- UNKNOWN: отправка/ACK неоднозначны; не повторять печать.
- FAILED: подготовка/авторизация/проверка отказала или разрешение отсутствует; не считать успехом.

До спулера создаётся постоянный журнал O_EXCL + fsync в `%LOCALAPPDATA%/GRIT-WMS/USB-Bridge`. Повтор того же ticket запрещён. Сервер атомарно делает QUEUED → SENDING, затем SUBMITTED/UNKNOWN. Возврат USB-задания в QUEUED запрещён даже общей функцией переходов с reviewed evidence. Потеря ответа claim оставляет SENDING без автоматического восстановления очереди.

Windows привязан к `http://127.0.0.1:18769`, идентичности isolated PG17, Windows-принтеру и конкретному ticket. Ping проверяет привязку, claim запрашивает точный ticket/stand: новый заказ молча не подхватывается. Конфигурация `%LOCALAPPDATA%/GRIT-WMS/USB-Bridge-Config/binding.dpapi` зашифрована текущим пользователем и защищена DACL. Серверный enrollment имеет 0600; stdout SSH захватывается в память, не выводится. Windows-переменная GRIT_PR192_USB_AGENT_TOKEN больше не используется.

Постоянный request_id сохраняется на HOSTKEY до HTTP. Повтор после UNKNOWN/SUBMITTED возвращает старый статус. Новая отдельная физическая попытка требует отдельной осознанной процедуры, а не удаления журнала/сброса задания. CLI автоматического повтора не предоставляет.

## Ограничения

- Оператор должен подтвердить бумажный результат, QR и размещение на **58×40 мм**. Ранее использовался другой рулон; геометрия физической печати не подтверждена.
- Это synthetic pilot: постоянный Windows service, несколько принтеров и эксплуатационное управление ключами не реализованы.
- Новых экранов/меню сотрудников не добавлено. Старый `/demo/worker-qr` остаётся тестовым harness, не переносится в production. Целевая интеграция — существующий вход по бейджу, QR принтера в существующем сканере и автоматическая маршрутизация без выбора заказов/постоянных manager approvals — отдельная производственная задача.
- Production WMS/БД, DNS, Caddy, реальные данные и интеграции не менялись. Merge/deploy main/GitHub Actions не выполнялись.
- Это не полная проверка GRIT. Fake-spooler не доказывает выход бумаги.

Повтор серверных тестов: `bash deploy/verify_grit_usb_bridge_offline.sh "$PWD"`, затем `bash deploy/verify_line_printer_print_queue_pg_isolated.sh "$PWD"`. Windows DPAPI: `py -m unittest discover -s tests/printing -p test_usb_config_windows.py -v`.
