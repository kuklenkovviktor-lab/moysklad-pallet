# PR211 — original WB sticker print: release gate

Status: **offline prototype only**, not production. No warehouse, real WB account,
real employee data, customer data, printer hardware or network access in tests.

## Already confirmed
- PR210 physical **synthetic** 58×40 print was observed by operator with
  `GRIT WMS / USB DEMO ONLY / NOT WB`. This is not proof of an original WB label.
- PR211 maps WB v11 order, original sticker code, persisted unit barcode,
  article and a unique active cell to a server-verified line.
- PR211 rasterizes the **original** recognized 58×40 PDF page into 203dpi,
  single-copy TSPL BITMAP. Nothing is generated by guessing sticker digits.
- PR211 has an offline **encrypted SQLite outbox prototype**: unique
  account/order, AES-256-GCM, payload hash, device authorization expected from
  server, one claim-before-spool, SUBMITTED vs UNKNOWN, no retry. The Windows
  RAW submission seam is callback-injected and tested with a fake spooler.

## NOT COMPLETE — no production merge or deployment
1. Actual WB PDF format: current strict parser recognizes a particular
   `WB <11 digit>` text structure. The nine-character / `*` sticker variants
   **must not be assumed compatible**. Test the parser separately on synthetic
   representative files. No actual warehouse PDF is required or permitted.
2. **Disposable PostgreSQL 17 queue prototype now implemented** in
   `services/printing/wb_original_pg17_outbox.py`: advisory locking,
   unique per-order staging, authorized-device seam, durable CLAIMED,
   AES-256-GCM, and original TSPL bitmap. It calls the **same**
   `_send_exactly_one` RAW spool function copied unchanged from PR210, through
   a **fake** Windows spooler. Production PG migration, real HTTP/device
   authentication, permissions and retention are NOT implemented.
   Never attach these synthetic tables directly to production.
3. Bind staging and claiming to existing GRIT employee/shift session,
   manager upload role, signed printer QR, explicit printer-id→USB-device
   allowlist, scoped device token and double-check of current order status.
   The current `authorized_device=True` flag is only a test-host placeholder,
   **not HTTP authentication**.
4. Implement protected original PDF ingestion, short retention, max size
   and page count, barcode/order binding audit, encryption-key rotation and
   deletion. Current legacy PDF preview is diagnostic-only, **does not save PDF**.
5. Merge compatible code from PR210 (synthetic USB) and PR211 only after
   a security review; original payload must pass the existing one-write
   driver function, DPAPI journal and no-retry rules. Never remove the
   `NOT WB` guard from the synthetic demo.
6. Run isolated PG17 regression + fake Windows spooler under own HOSTKEY
   runner. Check wrong-line/multi-cell, duplicate documents, races, cancellation,
   status changes after queueing, clock skew, API unavailability, corruption,
   partial USB write and ACK uncertainty. No live testing at employer warehouse.
7. Only after synthetic end-to-end verification may a specifically permitted
   test environment be considered for rollout. `main` and production stay
   unchanged until explicit authorization and rollback/backup readiness.
