# GRIT WMS: печать по линиям, этап 1 (#192)

## Зафиксированное правило

**Один заказ → один принтер.** Допустим только принтер, который покрывает все
подтверждённые линии *каждого* товара заказа. Не делить заказ между принтерами.
Если хотя бы одна позиция отсутствует на карте, имеет несколько подтверждённых
линий или выбранный принтер не покрывает все линии — отказ, разбор руководителем.

## Реализовано в этом PR

- `line_printer_routing.py`: чистое офлайн-решение о допустимости назначения.
- `tests/test_line_printer_routing.py`: 10 синтетических сценариев.
- Заказы с WB-статусом не `confirm` или с локальным статусом не `pending`
  не маршрутизируются.
- По существующим бронированиям выдаётся отказ, но **постановка блокировки
  в БД ещё не реализована**.
- Линию определяет существующая `warehouse_map.line_of()`.
- Для входных привязок обязательны `active=True`, `confirmed=True`.
  Эти флаги обязаны получаться из доверенного слоя чтения текущих активных
  `replenishment_locations` и подтверждённых `cell_sku_assignments`,
  а не из данных телефона или произвольного запроса.

## Не реализовано и запрещено использовать в production

- Реестр принтеров, управление линиями и защищённые QR 58×40.
- Серверная проверка бейджа/прав и атомарное бронирование между терминалами.
- Адаптер проверки актуального каталога, таблиц и локальной очереди WB.
- Печать рабочих этикеток, получение задания агентом и подтверждение физической печати.
- Подключение к действующим страницам GRIT. Флаг функции отсутствует: код
  никак не вызывается из рабочих маршрутов и ничего не переключает.

## Следующий этап

1. Создать изолированную схему и API менеджера для принтеров/линий с флагом
   `GRIT_LINE_PRINTER_ROUTING_ENABLED=0` по умолчанию.
2. Создать неизменяемый непрогнозируемый QR-идентификатор принтера, отдельно
   от авторизации сотрудника. Срок действия/отзыв должны быть продуманы.
3. Построить доверенное чтение подтверждённых товарно-ячеечных назначений,
   с чёткой обработкой дублированных артикулов, SKU и упаковок.
4. Реализовать транзакционное `UNIQUE(account, order_id)` бронирование и
   журнал попыток/причин отказа; исключить гонку между терминалами.
5. Только после offline синтетических тестов привязать кнопку менеджера
   для просмотра виртуального маршрута.
6. Отдельным PR спроектировать печатный агент для реальных WB-стикеров.

## Запуск теста (только изолированная копия)

```bash
python -m unittest discover -s tests -p 'test_line_printer_routing.py' -v
```

Избегать окружения с рабочей БД или токенами. Текущий код не требует
сети, принтера и изменений конфигурации сервера.
