# GRIT WMS: коммерческий интерфейс контроля печати (phase 9)

Дата: 26.11.2026. Продолжение issue #192; базовая ветка PR #205 (draft).

## Задача

Не менять проверенную логику QR -> очередь -> виртуальный агент. Убрать из менеджерского UI тестовые технические обозначения, показать имена принтеров и линии, выделить операционно важные состояния.

## Что сделано

- Отдельный темный адаптивный GRIT-экран: frontend/pages/printing_manager_demo/index.html + style.css.
- Четыре показателя по ВСЕМ синтетическим заданиям: в очереди, передано виртуальному агенту, требует внимания (FAILED + UNKNOWN), всего. Счетчики не рассчитываются по ограниченной выдаче 100 строк.
- Карточки принтеров: имя, линии, активность, количество QUEUED, количество требующих внимания и последнее известное состояние.
- Таблица последних 100 заданий: имена принтеров вместо внутренних printer_id, русские названия статусов, поиск по заказу, фильтры по принтеру и состоянию. Безопасный вывод через textContent.
- История последних 100 событий с читаемыми переходами; сырые технические коды доступны в раскрываемом блоке.
- Диспетчеризация неизменна: ОДНО синтетическое задание за клик, POST принимает только printer_id и CSRF; нельзя задать заказ или режим из браузера. Если QUEUED=0, кнопка неактивна.
- SUBMITTED означает только виртуальное подтверждение, а НЕ физическое PRINTED.

## Следующий разрешаемый этап: физический тестовый Xprinter 58x40

Этот PR НЕ содержит USB, CUPS или Windows-spooler интеграции. Требования к следующему отдельному испытанию:

1. Использовать выделенный тестовый Xprinter, подключенный к отдельному разрешенному ПК вне склада работодателя; только синтетические заказы и этикетки. При необходимости получить разрешение владельца устройства.
2. Определить ОС тестового агента, точную модель и идентификатор тестового принтера. Жесткий allowlist единственного устройства и synthetic-only режим.
3. Уточнить протокол печати данной модели (TSPL/ZPL/ESC-POS): нельзя угадывать. Проверить формат 58x40, QR, размеры, кодировку, поля и ориентацию.
4. Выполнить одну явную физическую печать синтетической этикетки. Проверить размер, читаемость QR, смещение и реальные границы.
5. Разделить статусы SUBMITTED (принято spooler), PRINTED (достоверно подтверждено устройством либо оператором) и UNKNOWN (исход неясен). Никакой автоматической перепечатки после uncertain/timeout.
6. Зафиксировать журналы и снимки, затем пройти регрессию QR, авторизации, конкурентных запросов, ошибок, восстановления. Prod-развертывание только по отдельному решению владельца проекта.

Виртуальное SUBMITTED не может считаться подтверждением физической печати.
