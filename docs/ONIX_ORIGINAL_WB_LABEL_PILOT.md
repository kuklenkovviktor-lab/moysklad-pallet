# ONIX · Первый оригинальный ШК WB на тестовом Xprinter (локально)

## Что уже проверено

Связь ONIX Render → Windows → USB → `ONIX-TEST-XP460B` успешно
напечатала тестовую этикетку `ONIX TEST / NOT WB`, статус `submitted`.

**Этот следующий шаг пока выполняется локально**, поскольку ONIX пока не
хранит оригинальные страницы PDF. Это сознательно: тестируем качество
конкретного WB-штрихкода до массовой отправки из облака.

## Размер этикеток на складе

Оба Xprinter XP-460B используют 58×40 мм. Предыдущая проба WB была
подготовлена для 40×30 мм, поэтому на физической этикетке оставалось
много пустого места. Новый модуль использует 58×40 мм, сохраняя
соотношение сторон оригинального QR и штрихкодов.

**Перед новым тестом скачай обновлённый `onix_wb_label_pilot.py`.**
Первый уже отпечатанный ШК не повторяем.

## Подготовка

1. Оставь рабочий Xprinter XP-460B **по умолчанию**. Второй:
   `ONIX-TEST-XP460B`. Этикетки на обоих принтерах **58×40 мм**. Этот модуль печатает WB именно 58×40 мм с белыми полями 1,5 мм, не искажая ШК.
2. В папке `Downloads` должны лежать:
   - `onix_usb_print_test.py` (уже скачан для первой пробы),
   - `onix_wb_label_pilot.py` (скачать из репозитория),
   - `fbs_pdf_labels.py` (существующий строгий парсер ONIX).
3. Установи зафиксированную версию библиотеки PDF (ту же, что использует ONIX
   на сервере). **Не используй** команду с `PyMuPDF>=2.0,<3`: у версии
   2.0 появились дополнительные зависимости, включая ONNX Runtime, которые
   могут отсутствовать для Python 3.15.

   ```cmd
   py -m pip install "PyMuPDF==1.26.5"
   py -c "import pymupdf; print('ONIX PDF OK:', pymupdf.VersionBind)"
   ```

   У версии 1.26.5 есть Windows x64 wheel с `abi3`, но **официальная
   поддержка заявлена до Python 3.14**. На Python 3.15 сначала проверяем
   запуск этой команды; если импорт не работает, используем Python 3.14,
   а не обходим ошибку и не печатаем вслепую.

   Установленный для первого теста `pywin32` сохраняем.
4. Сохрани **исходный PDF с товарными листками и стикерами WB** в Downloads.
   Не вырезай вручную страницы и не редактируй исходный файл.
   Подойдёт PDF, который уже разбирался в модуле ONIX
   «Загрузка PDF FBS», если по нему показано отсутствие структурных ошибок.
5. Выбери **один 11-значный ШК WB** из результата анализа PDF ONIX.
   Не путай его с баркодом товара (13 цифр).

## Шаг 1: только предпросмотр, ничего не печатает

В CMD, открытом в папке Downloads:

```cmd
py onix_wb_label_pilot.py --pdf "orders.pdf" --barcode 59299122174 --preview
```

`orders.pdf` замени на имя своего PDF. Пример `59299122174` тоже
**замени на настоящий ШК из своего PDF**. Эти значения условные.

В той же папке появятся `ONIX_WB_<ШК>_PREVIEW.png` и
`ONIX_WB_<ШК>_REVIEW.json`. Открой **PNG** и сравни его с исходным
стикером WB: код, расположение, читаемость, отсутствие обрезки.
Картинка соответствует будущей печати **58×40 мм (464×320 точек при 203 dpi)** с белыми полями 1,5 мм. Масштабирование пропорциональное, без обрезки.

Если ONIX ответит, что PDF не прошёл структурную проверку, размер
страницы не соответствует этикетке, либо ШК повторяется,
**не обходи ограничение и не запускай печать**.

## Шаг 2: ОДНА ручная печать после проверки изображения

```cmd
py onix_wb_label_pilot.py --pdf "orders.pdf" --barcode 59299122174 --print-one --confirm-code 59299122174
```

ШК и имя PDF должны быть **такими же, как на этапе предпросмотра**. Для нового теста после исправления формата выбери **другой, ещё не печатавшийся ШК**. Старый `59344547000` уже напечатан, его историю и блокировку сохраняем.
Программа подтверждает неизменность PDF и картинки по SHA-256,
не позволяет выбрать рабочий принтер по умолчанию и делает
**только одну отправку** RAW TSPL на `ONIX-TEST-XP460B`.

Команда не допускает повторной печати при статусах `claimed`,
`submitted` и `uncertain`. Файлы `.json` и `.lock`
не удаляй: они защищают от случайных дублей.

После печати **сравни бумажный ШК с исходным PDF и отсканируй его**.
Пробную этикетку не наклеивай на товар и не отдавай в FBS.

## Важно

- Этот сценарий не использует ключ `ONIX_PRINT_AGENT_TOKEN`, Render,
  производственные заказы, остатки или очереди сборщиков.
- Состояние `submitted` подтверждает отправку в Windows, а не
  успешное сканирование WB.
- Следующий этап только после этой проверки: хранение оригинальных
  страниц PDF в ONIX, распределение по линиям и защищённая очередь
  реальных заказов. Для реальных ШК сперва **замени раскрытый на
  прошлых скриншотах ключ агента** в Render.
