# PR192: QR принтера → автоматическое добавление в очередь (synthetic stage)

**Дата:** 26.11.2026. Основа: draft PR #199, issue #192.
Нет production deployment, live WB или физической печати.

## Целевой цикл

Штатный экран сборки GRIT → сотрудник сканирует QR → сервер из
зарегистрированного принтера определяет текущие линии → отбирает локальные WB
заказы, проверяя статусы/очередь/каталог/ячейки/исходный стикер → атомарно
обновляет PostgreSQL очередь. Сотрудник НЕ выбирает ID заказа, НЕ управляет
резервированием или состояниями печати.

## Добавлено

- services/printing/qr_scan.py — backend service, принимает ТОЛЬКО
  доверенные employee_id/shift_id и сканированный QR от server boundary.
  Читает candidates из локальных wb_fbs_orders + wb_fbs_picking_queue с
  синтетическим account_id, только confirm/pending. Все признаки готовности
  перепроверяются под замками PostgreSQL непосредственно перед INSERT через
  validate_locked_synthetic, включая текущие линии принтера, отзыв QR,
  смену/активность сотрудника, каталог и привязки ячеек.
- Изолированная таблица synthetic_pr192_print_stickers обязательна для
  проверки наличия исходного стикера. Тесты кладут в неё только выдуманные
  строки. Никаких WB QR кодов из production. Встраивание настоящих стикеров
  и форматирование этикетки в этом этапе отсутствуют.
- services/printing/qr_http_synthetic.py — Flask Blueprint factory без
  регистрации в app.py. POST /synthetic/pr192/print-queue/scan принимает
  строго {"qr": "...", "csrf": "..."}; employee/shift берутся только из
  server-side session identity, не из JSON. CSRF обязателен.
  Factory make_real_wms_synthetic_autoqueue_blueprint использует штатный
  wms.get_session_employee() при создании синтетического приложения.
- tests/printing/test_qr_autoqueue.py — 21 synthetic HTTP/PG test case,
  включая повторный QR, новые поступления, изменение линий без ротации QR,
  конкурентные обращения, отмену, отсутствие оригинального стикера,
  деактивацию бейджа, выход из смены, закрытие сборки, CSRF и spoofing.
- deploy/verify_line_printer_print_queue_pg_isolated.sh расширен новым
  набором после существующих 16 PG17 тестов.

## Запуск изолированных тестов

Для проверки нужен checkout ветки этого PR и disposable PG17 на HOSTKEY.
Запуск:
  bash "$DIR/deploy/verify_line_printer_print_queue_pg_isolated.sh" "$DIR"

Скрипт сам создаёт отдельную internal Docker network, временную PostgreSQL 17
на tmpfs, не пробрасывает портов, не использует production Compose/volumes.
После завершения удаляются только созданные им контейнер и сеть.

**В этом PR новые QR→PG тесты пока НЕ запущены.** Подтверждённый прежний
прогон 17 SQLite + 16 PG относится к состоянию PR #199 до этого инкремента.

## Оставшиеся ограничения

1. Нет регистрации route в текущем режиме сборки; не трогать production.
2. Нет подтверждения реальной валидности исходного WB стикера: только
   наличие выдуманной строки в синтетической таблице.
3. Нет реального Windows USB print-agent, физического PRINTED, safe retries.
4. Нет связи с реальным состоянием доставки/печати на принтере;
   queued_new — не число физически напечатанных этикеток.
5. Нет живой менеджерской панели исключений, мониторинга и reprint.
6. Нет защиты от очень больших очередей через порционную обработку;
   сейчас все синтетические кандидаты читаются одним запросом.
7. Надо отдельно протестировать адаптер с реальной WMS session auth на
   одноразовой SQLite WMS + PG17; текущий HTTP набор использует stand-in
   authenticated_employee(), а factory с настоящей auth добавлен, но не
   включён в production.
8. Нужен security review, включая гонки отключения принтера, статус WB перед
   фактическим spooler submit и отказ от неизвестного печатного результата.

**Не merge/deploy до изолированных проверок и ревью.**
